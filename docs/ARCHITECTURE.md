# Architecture

Tandem Audio has a C++ portable core, a Windows host/client engine and WPF shell, and a SwiftUI/AVAudioEngine iPhone client. The core owns the versioned audio packet serializer, clock calculations, jitter buffer, drift estimator/corrector, and playback latency math. It has no GUI or Apple/Windows audio API dependency. `desktop/` owns miniaudio playback, UDP/TCP sockets, room state, multicast discovery advertising, and the CLI. `desktop/gui/` discovers rooms and starts the engine as a child process. `ios/` owns Network.framework transport, Bonjour browsing, AVAudioSession route handling, AVAudioEngine playback, and the phone UI.

The Windows room host is authoritative for stream frame numbers and scheduled play/pause/seek/stop commands. Audio goes by bounded PCM UDP datagrams to each joined member; control goes by TCP; periodic four-timestamp probes estimate host/client monotonic clock offset. The iPhone converts host presentation times into local render scheduling, keeps a bounded jitter queue, and applies small drift corrections. Output latency compensation combines the platform estimate with optional route-specific manual adjustment. These estimates do not replace acoustic calibration.

Room membership and per-client destinations are protected by the host's room/control locks. Network threads do not write to an audio callback. The receiver validates every header and bounds buffering. The WPF GUI starts and stops one engine process and queries the loopback-only `MEMBERS` control endpoint. For detailed wire transport see [Wi-Fi architecture](WIFI_ARCHITECTURE.md), [protocol](PROTOCOL.md), and [rooms](ROOMS.md).
